# LastRO 服务器配置

内置 profile 是离线兜底。IWA 启动后使用 Direct TCP + TLS 443 端口，按固定路径读取官方 `game.lastro.cn/ro/Online.js`，只解析文本中的服务器表及 PacketCrypt 静态数组，不执行、加载或替换远程 JavaScript。下载成功后，先完整验证结构，再原子替换 localStorage 中的 `lastro-official-online-profiles-v1`；下载失败或缓存过期（90 天）时保留内置值。浏览器 Web 构建没有 Direct TCP 权限，因此不会自行刷新，仍可读取已有有效缓存。

来自 2026-10-10 用户提供的 3.2 MiB 官方 Online.js 快照（源文件中没有 `nid=6`）：

| nid | 地址 | 端口 | version | langtype | 传输代理元数据 |
| --- | --- | ---: | ---: | ---: | --- |
| 0 | 192.168.101.89 | 36666 | 45 | 3 | ws://192.168.101.89:5999/ |
| 1 | port.lastro.cn | 38569 | 45 | 3 | wss://port.lastro.cn/ |
| 3 | 103.8.222.164 | 28569 | 45 | 3 | wss://port.lastro.cn/ |
| 4 | port.lastro.cn | 29569 | 45 | 3 | wss://port.lastro.cn/ |
| 5 | 103.8.222.164 | 26569 | 45 | 3 | wss://port.lastro.cn/ |

`ClientVer=3` 的 PacketCrypt 三元组是 `[1205481659,453061308,592073252]`，其他 ClientVer 使用 `[1205481642,453065386,592073252]`。源文件中还包括 63 组按日期索引的 PacketCrypt 数据；客户端缓存这些数据，但最终游戏加密仍使用官方对应 ClientVer 三元组，日期表不是额外密钥的推测来源。

本地默认：3 转服 nid=3 使用 `103.8.222.164:28569`、`langtype=3`；2 转服 nid=5 使用 `103.8.222.164:26569`、`langtype=3`；App 服 nid=6 不在官方快照中，因此保留 `port.lastro.cn:27569`、`langtype=4` 和原有私服密钥作为兜底。

缓存中的 `relayEndpoint` 保留官方所发布的代理路径。传统中转连接会优先使用经过验证的 `wss://*.lastro.cn/`（无自定义端口、查询字符串或路径），如果官方值超出这个范围则回退内置的 `wss://port.lastro.cn/`。该元数据绝不会被作为脚本执行。现有安全约束禁止将外部脚本直接作为可执行资源加载。每次真正登录前会重新读取缓存并刷新所选服务器连接参数；后台拉取永不阻塞登录。

**安全说明（2026-10-10 更新）：** 官方 `Online.js` 在固定域名的 443 端口经第三方 TLS 下载器加密传输；此条公开元数据下载目前未启用证书链验证，因此仍可能受到主动中间人篡改。客户端只做静态解析，不执行下载的 JavaScript。用于 CSRF 和账号凭据的登录辅助 POST 强制启用证书验证。今后应尽可能为所有元数据验证服务器身份或引入可信签名。
